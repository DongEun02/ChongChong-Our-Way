## 문서 구조

```text
.
├── README.md
└── docs/
    └── <topic>.md
```

- `README.md`: 저장소 소개와 전체 문서 목록을 관리합니다.
- `docs/`: 주제별 기술 문서를 저장합니다.

## 작성 원칙

- 해결책보다 문제와 배경을 먼저 설명합니다.
- 여러 선택지와 각각의 장단점을 비교합니다.
- 최종 결정과 그 근거를 명확히 남깁니다.
- 성능 수치나 테스트 결과는 재현 방법과 함께 기록합니다.
- 외부 자료를 참고했다면 출처를 표기합니다.
- 이후 구현이나 결정이 바뀌면 기존 문서도 함께 갱신합니다.

## 문서 템플릿

새 문서는 아래 형식을 기본으로 작성합니다. 주제에 맞지 않는 항목은 생략해도 됩니다.

```markdown
# 제목

## 이유 확인 - 시작 전

> 이 요구사항이 왜 주어졌는지, 어떤 경험을 만들기 위한 것인지 파악합니다.
> 적용 전 상태(문제, 불편, 위험, 비효율, 학습 공백)를 먼저 남깁니다.


## 적용 - 실제 서비스에

> 기술을 학습하고, 실제 팀 프로젝트 서비스에 적용합니다.

## 관찰 - 적용 후

> 적용 후 무엇이 달라졌는지 확인합니다.
> 데이터, 로그, 화면, 대시보드, 팀 피드백, 사용자 반응 등 확인한 것을 남깁니다.

## 기록과 설명

> 수행 내용과 판단 근거를 문서로 남깁니다.



## 참고 자료

- [자료명](https://example.com)
```
